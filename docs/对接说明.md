# 对接说明（DSH 引擎）

本文件维护本插件与官方 DeepSeek Harness（dsh）之间的对接进度：每轮官方发版后重新盘点一次，
更新下面的四类差异表与验证边界。Command Code CLI 侧的对接见
[模型与上游同步](agent-reference/model-catalog.md)与 `dsh-commandcode-upstream` 技能。

## 二、四类差异对照

| 类别 | 内容 |
| --- | --- |
| 双方都有 | 消息与内容块、结构化错误、凭据解析、易变设置、图片卸载、严格远端编解码、五个客户端插槽、会话费用投影、`addition-only`（仅新增）工具声明 |
| 上游有、我方未接 | `systemPromptUpdate: 'in-history'`（历史内系统提示替换）、原生工具延迟激活语义、`prepareCall` 可选准备回调、上游 `idleWatchdog` 的挂起读取期限修复 |
| 我方有、上游没有专用契约 | Command Code 账号轮换与网关探测、三协议 wire 转换、网关能力快照与价格展示、`x-command-code-version` 与零数据保留请求头 |
| 双方都没有 | 配置与凭据的跨服务原子事务、对在途请求追溯改写配置 |

差异细节：

1. **消息、内容与错误**：`RequestMessage`、`GenerateOptions`、`ContentBlock` 结构与 `LlmError` 构造及
   `failure` 事实本次均未变，适配器不需要改动。
2. **服务契约**：Agent 事件（`agent/status`、`agent/request-error`）、设置、凭据、附件公开源码与 Typert
   严格描述符协议本次未变；会话投影的 `register()` 改为直接返回 Cordis 清理函数，插件现有的
   `c.effect(() => registry.register(...))` 写法已经匹配。
3. **新增但向后兼容**：`prepareCall(config, signal?, configure?)` 增加可选同步回调，旧调用方式继续成立，
   本适配器不使用第三参数。
4. **宿主内部行为变化**（不影响插件接口，但影响验收预期）：请求准备完成后刷新运行时上下文（首次请求
   替换旧快照、重试可录入变化）；代理卸载改为先停流、再释放作用域、排空并关闭会话写入、最后撤销注册。
5. **刻意未宣告的能力**：`in-history` 系统提示替换与原生工具延迟激活。能力标记必须与实际 wire 行为一致：
   插件继续使用前导系统提示与完整的活跃工具列表，未实现对应语义前不宣告这些能力。

## 四、验证证据与边界

1. **真实引擎矩阵**：`npm run test:engine` 对每个已声明引擎各跑一遍 —— 发布入口加载、静态具名导入审计、
   客户端 `require()` 种子审计、易变设置契约、持久化图片卸载契约、账号开通观察流取消、三协议 22 个流
   终态场景、网关切换期间的请求快照隔离。三个引擎（`0.2.0-rc.2`、`0.2.1-alpha.1`、`0.2.1-alpha.2`）全部通过。
2. **逐引擎隔离安装**：`npm run test:install` 为每个已声明版本各建一个全新的 pnpm 10.34.5 generation，
   安装时把该版本的必需 Harness peer 一起钉死，再断言锁文件解析出的 `@deepseek-ai/dsh-llm` 恰好是目标版本。
   三个版本全部通过。
3. **未覆盖**：浏览器实际渲染、真实账号与付费请求、凭据持久化、跨平台运行、长期运行稳定性，以及卸载
   期间最终事件排空与重试预算隔离，都需要实际环境验收，不能由本地绿色检查推定。
4. **读流挂起已修复（2026-10-10）**：插件自有的读流原先依赖 `reader.cancel()` 唤醒挂起的 `read()`，遇到既不结算
   读取也不响应取消的响应体会让空闲期限、调用者取消和消费方结束一起卡死。现在读循环用「唤醒闸门」自己结束
   等待（取消优先，其次 `TIMEOUT`），被放弃的读取迟到拒绝就地吞掉。审计阶段先在 `0.2.0-rc.2` 上复现出这一
   既有缺口，修复经授权后单独实施，详见[决策记录第八章](决策记录.md#八dsh-引擎兼容范围与验证边界)与
   [协议参考](agent-reference/adapter-protocol.md)。
