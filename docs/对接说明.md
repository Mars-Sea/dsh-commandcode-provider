本文件维护本插件与官方 DeepSeek Harness（dsh）之间的对接进度：每轮官方发版后重新盘点一次，
更新下面的四类差异表与验证边界。Command Code CLI 侧的对接见
[模型与上游同步](agent-reference/model-catalog.md)与 `dsh-commandcode-upstream` 技能。

## 二、四类差异对照

| 类别 | 内容 |
| --- | --- |
| 双方都有 | 消息与内容块、结构化错误、凭据解析、易变设置、图片卸载、严格远端编解码、五个客户端插槽、会话费用投影、逻辑历史读取与精确分支边界、`addition-only`（仅新增）工具声明、`imageRequestTarget`（图片请求目标） |
| 上游有、我方未接 | DeepSeek Search／Fetch API（rc.2 新增 `dsh-web-deepseek-api`，在网页搜索设置中开启）、DeepSeek-V4.1-Flash-1017 模型标签插槽（rc.2 新增 `dsh-client-ui-deepseek-model-label-1017` 与 `conversation.input.model.label` 插槽）、`systemPromptUpdate: 'in-history'`（历史内系统提示替换）、原生工具延迟激活语义、`prepareCall` 可选准备回调、Typert 严格投影（`input({strict:true})` 与 JSON Schema）、插件市场（plugin-market 系列，默认关闭）、Host 发布版本一致性闸门（仅影响开发态热更新，见第 9 条） |
| 我方有、上游没有专用契约 | Command Code 账号轮换与网关探测、三协议 wire 转换、网关能力快照与价格展示、历史模型成本分析与固定工作量试算、`x-command-code-version` 与零数据保留请求头、压缩摘要的成本对账口径（`summaryTokens`） |
| 双方都没有 | 配置与凭据的跨服务原子事务、对在途请求改写配置 |

差异细节：

1. **破坏性变化之一（代码）：`WebRuntime` 的搜索选择从私有字段改为易变配置引用。** alpha.4 及更早的
   `WebRuntime` 在实例上持有 `private readonly searchProviderId: string | undefined`，`search()` 每次调用读取它；
   插件因此直接改写这个实例字段。rc.2 删掉了该字段，选择改由构造注入的易变配置 `config.searchProvider`
   （`z.string().volatile()`，解析为 `{ get() }` 引用）承载，`search()` 每次调用 `this.config.searchProvider.get() ?? env`。
   宿主仍未提供公开的运行时选择接口。这一变化的**失败模式是静默**：旧写法给一个已不存在的属性赋值不会抛错，
   但 `search()` 读不到它——toggle 打开后搜索仍走原来的后端，或关闭后无法恢复。处置见第五章第 3 条：
   插件同时支持两种形状，新形状通过 cosmokit 的跨副本写协议 `Symbol.for('cosmokit.volatile.write')` 替换引用值。
   由于用户要求向下兼容，适配后的声明同时覆盖 `0.2.0-rc.2`（旧形状）与 `0.2.1-rc.2`（新形状），
   两种形状都在真实引擎矩阵里各跑了一遍。
2. **破坏性变化之二（声明）：宿主准入判定仍然只读 `engines.dsh`。** rc.2 的
   `app-boot/src/plugin-compatibility.ts` 与 alpha.4 相比源码零变化（`packages/boot/` 本轮无源码改动），
   规则不变：只要包自带 `engines.dsh`，`@deepseek-ai/dsh*` peer 就完全不参与判定。旧声明
   `0.2.0-rc.2 || 0.2.1-alpha.4` 不含新引擎，插件行会被预检禁用、作为 profile bundle 被静默跳过、
   `dsh plugin add` 在 pnpm 之前被拒绝。已同批扩展为 `0.2.0-rc.2 || 0.2.1-rc.2 || 0.2.1-alpha.4`（保留上一稳定 RC，不替换），见第五章第 1 条。
3. **插件直接导入的宿主包中，除 `dsh-web` 外源码零变化**：`dsh-llm`、`dsh-settings`、`dsh-credentials`、
   `dsh-commands`、`dsh-typert-protocol`、`dsh-timeout`、`dsh-launch-environment`、`dsh-agent`、`dsh-attachment`、
   `dsh-api-remotes` 的 `src/` 与基线逐字节相同（`packages/llm/*`、`packages/settings`、`packages/credentials`、
   `packages/api/remotes` 等目录本轮无源码改动），`dependencies`／`peerDependencies`／`peerDependenciesMeta`／
   `dsh` 块只有版本号变化 —— 无新增必装 peer、无移除 peer、无范围语义变化。`dsh-web` 的变化仅限第 1 条所述
   `WebRuntime` 选择字段（`WebError` 与 provider 注册接口未动）。
4. **Web 静态种子表零变化**：`packages/client/web/src/seed.ts` 与 `platform.ts` 两版逐字节相同，
   `lib/client.js` 的三个 `require()` 目标（`react`、`react/jsx-runtime`、
   `@deepseek-ai/dsh-client-ui-primitives`）仍然可解析；`packages/client/modules`、`packages/client/hmr` 本轮
   无源码改动。`dsh.client.inject` 的三个包（`dsh-client-locale`、`dsh-client-ui-settings`、`dsh-api-remotes`）
   仍各自声明 `dsh.client` 清单，模块图不变。
5. **五个在用插槽的契约零变化**：`settings.section`、`settings.models.provider-card`、`sidebar.footer.action`、
   `main`、`conversation.composer.dock` 的名字、kind、owner props 与 outlet 渲染调用未变；`packages/client/ui-slots`
   的 `src/` 零差异，`packages/client/ui-settings-models`（provider-card 卡片的宿主侧）也零源码改动。
6. **上游新增两个客户端/宿主包，与插件无关**：`dsh-client-ui-deepseek-model-label-1017` 往
   `conversation.input.model.label`（`single`／`session`／`inline`）注册模型名标签，`ui-model-selection` 的
   `slots.ts` 随之声明该插槽并新增 `ModelLabelOwner`；`dsh-web-deepseek-api` 提供 DeepSeek 搜索/抓取后端。
   插件不注册该插槽、不依赖这两个包；模型选择器的 `conversation.input.model` 座位契约未变。
7. **`ui-settings-web-search` 有实质改写，但插件零引用**：该包把网页搜索设置卡片的组件、CSS module 与控制器
   一起重写（新增 `WebSearchCard.module.css`、`web-search-card-controller.ts`），用于承载 DeepSeek Search/Fetch
   开关；插件不导入它，自己的 `webSearch` 开关仍走 `llm-commandcode` 设置页与 `ctx.web` 选择写入。
8. **Cordis 与 Schemastery 从 alpha 通道转正**：alpha.4 配 `4.0.5-alpha.2` 与 `3.18.5-alpha.2`，rc.2 配
   `4.0.5` 与 `3.18.5`。既有声明 `~4.0.5-alpha.1`／`~3.18.5-alpha.1` 的 tilde 分支已覆盖正式版
   （`4.0.5 >= 4.0.5-alpha.1` 且 `< 4.1.0`），两个范围**不动**；锁文件中随引擎配对的 6 个 Cordis／Schemastery
   条目已从 `-alpha.2` 精准换成正式版。
9. **新增但默认关闭**：插件市场系列（`dsh-plugin-market`、`dsh-plugin-market-index`、
   `dsh-client-ui-plugin-market`、`dsh-experimental-plugin-market-bundle`、`dsh-plugin-market-generator`）继续
   属 `OPTIONAL_BUNDLES`，默认关闭；客户端 Host 发布版本一致性闸门（`ReleaseChangeGate`）只影响开发态热更新，
   不改变插件契约。本轮两处均不需配合。
10. **未变的其他面**：`RequestMessage`、`GenerateOptions`、`ContentBlock`、`LlmError` 与模型能力类型
    （`packages/llm/*/src`）零变化；`toolUpdate: 'addition-only'` 在新引擎的真实工具历史检查中通过；
    审批 seam 仍然完全不接入（`src/` 无 `approval`／`pre-execute` 引用）。

## 四、验证证据与边界

1. **真实引擎矩阵**：`npm run test:engine` 对每个已声明引擎各跑一遍 —— 发布入口加载、静态具名导入审计、
   客户端 `require()` 种子审计、**宿主准入判定**、易变设置契约、持久化图片卸载契约、账号开通观察流取消、
   三协议 22 个流终态场景、网关切换期间的请求快照隔离、真实历史服务读取关闭会话与分支、严格分析远端校验。
   当前三个引擎（`0.2.0-rc.2`、`0.2.1-rc.2`、`0.2.1-alpha.4`）全部通过（`engine-load smoke passed on all 3
   declared-compatible engines`）。本轮先在**未改声明**的 `0.2.1-rc.2` 上复现了唯一失败项——
   `the host compatibility preflight REJECTS this plugin: {"engines.dsh":"0.2.0-rc.2 || 0.2.1-alpha.4"}`——
   其余检查（链接、具名导入、种子审计、设置契约、22 个流终态场景、网关、历史服务）在该引擎上已全绿，
   证明 `src/` 运行时只有第 1 条要改。改声明后矩阵三引擎通过。
2. **逐引擎隔离安装**：`npm run test:install` 为每个已声明版本各建一个全新的 pnpm 10.34.5 generation，
   安装时把该版本的必需 Harness peer 一起钉死，再断言锁文件解析出的 `@deepseek-ai/dsh-llm` 恰好是目标版本。
   本轮版本对：`0.2.0-rc.2`、`0.2.1-rc.2`、`0.2.1-alpha.4`。
3. **类型与测试**：在**升级后的 rc.2 开发依赖**下运行 `npm run typecheck` 与全量 1036 项测试，均通过；
   `npm run build` 产出两段构建。
4. **静态具名导入**：以真实 rc.2 引擎逐条核对 `lib/index.js` 的静态具名导入，全部存在 —— 具名导入缺失
   是 ESM（ECMAScript 模块）链接期致命错误，必须单独证明。`test:engine` 在 rc.2 上已单独跑过该审计。
5. **锁文件同步性**：按[《决策记录》第八章第 11 条](决策记录.md#八dsh-引擎兼容范围与验证边界)不重新解析整棵树，
   只精准替换 29 个 `@deepseek-ai/dsh*` 条目、6 个 Cordis／Schemastery 配对条目与根声明面：版本、`resolved`、
   `integrity` 取自 npm registry，非 dsh 条目逐字节不变、条目零增删、平台可选依赖分支保持完整。
   用 `npm ci --dry-run --ignore-scripts` 校验同步通过（100 个包全部解析为 rc.2）。
6. **未覆盖**：浏览器实际渲染、真实账号与付费请求、凭据持久化、跨平台运行、长期运行稳定性，以及 headless
   下「导出环境变量后能正常发请求」的端到端表现，都需要实际环境验收，不能由本地绿色检查推定。联网搜索的
   选择写入本轮只做了单元测试（两种运行时形状）与真实宿主的 `apply()` 集成测试，**没有**在真实浏览器里点一次
   toggle 再发一次搜索。
7. **本地环境残留（非插件缺陷）**：本机 web profile（`~/.dsh/profiles/web/cordis.patch.yml`）里
   `llm-deepseek-account` 条目的 `models: []` 属 alpha.3 那轮记录的旧值残留，按维护者决定暂不清理，因此本地
   启动会持续打印一条「1 entry did not activate」警告。该条目是上游账号 provider，失败为可选条目失败，
   commandcode 路由与其它条目的激活不受影响；此项未纳入自动化验证，也不构成插件缺陷。

## 五、本轮改动

1. **引擎声明向下兼容扩展**：`@deepseek-ai/dsh-*` peer 析取、`dsh.compatibility.dsh`、`engines.dsh`、
   `dsh.compatibility.dshReleases`、`devDependencies` 与 `package-lock.json` 同批扩展为

   `@deepseek-ai/cordis` 与 `@deepseek-ai/schemastery` 的范围**不变** —— rc.2 配对的 `4.0.5` 与 `3.18.5`
   落在既有 tilde 分支内。
2. **锁文件精准更新**：不重新解析整棵树（否则 `@rolldown/binding-*` 等无关依赖会被顺带升级），改为只替换
   29 个 `@deepseek-ai/dsh*` 条目、6 个 Cordis／Schemastery 配对条目及其根声明面；每个条目的 `version`／
   `resolved`／`integrity`／依赖声明取自 npm registry 的同版本清单。非 dsh 条目逐字节不变、条目零增删、
   平台可选依赖分支保持完整。
3. **联网搜索选择适配**（`src/web-search.ts`）：`applyCommandCodeSearchSelection` 抽出一层
   `selectionField()` 形状解析——实例是 rc.2 形状（自带 `config` 自己属性）时，读取与写入都走
   `config.searchProvider` 这个易变引用，写操作通过 `Symbol.for('cosmokit.volatile.write')` 完成（跨 ESM/CJS
   副本稳定，且不需要把 cosmokit 加成本插件 peer）；实例没有 `config` 时沿用旧私有字段；`config` 存在但引用
   不可写（手工构造或未来加固）时保持「已注册但未选中」且不抛错。语义与旧实现一致：启用时记住被顶掉的后端，
   关闭/卸载时只归还自己真正接管过的选择，预置 `commandcode` 时不回写 `undefined`（issue #26）。
4. **测试**（`tests/web-search.test.ts`）：新增 6 项 rc.2 形状用例——启用、关闭恢复、重复启用保留被顶掉后端、
   预置 `commandcode` 不回写、未配置回填 `undefined`、不可写引用不动实例且不抛错；宿主级 `apply()` 集成测试
   改为通过 `selectedSearchProvider()` 读取两种形状，三个已声明引擎共用同一套断言（该文件测试数
   从 14 增至 20 项，全套 1036 项）。
5. **文档同步**：本文件、[引擎兼容](agent-reference/engine-compatibility.md)（兼容范围、配对、`test:engine`
   说明与第三节新增 rc.2 轮次）、[决策记录](决策记录.md)第八章第 13 条、`CHANGELOG.md`、两份 README、
   [仓库地图](agent-reference/repository-map.md)、[账号与重试](agent-reference/accounts-and-retry.md)、
   [客户端与设置](agent-reference/client-and-settings.md)、[模型成本与性能分析](模型成本与性能分析.md)。
6. **刻意不做**：DeepSeek Search／Fetch 后端不接入（上游新包，与 Command Code 搜索 provider 是并列选择，
   接入属独立功能）；`conversation.input.model.label` 模型标签插槽不注册（只影响模型名的展示，不改插件契约）；
   `0.2.1-alpha.5` 不纳入本轮验证（alpha 通道保持上一轮已验证版本，待下一轮审计）；插件市场与 Host 发布
   版本一致性闸门不需要插件配合。
