# 模型成本与性能分析（问题 #79）

统计口径已获用户确认，长期约束记录于[《决策记录》第九章](决策记录.md#九模型成本与性能统计)。

## 一、实现与统计口径

1. 入口为“设置 → Command Code → 查看模型用量、成本与性能分析”，或已有额度面板中的“模型分析”。无需打开侧栏额度卡片。只在打开分析页或手动读取时扫描历史，不后台轮询历史。
2. 最近会话按最后一次记录的 Command Code 请求时间排序，取 1–100 个含该提供商请求的会话。日期范围按浏览器本地日历，开始日包含、结束日包含；远端采用 `[from, to)` 半开区间，上限 366 天。按请求开始时间归属，不按会话创建时间裁切请求。
3. 每次步骤和已开始的宿主重试各是一条请求；同一次尝试的多份用量报告用最后一份覆盖，重试另计。这里统计的是宿主记录的模型尝试，不包含适配器内部的网络重试或协议回退。分支继承前缀只恢复模型选择，费用只计自有请求。失败、已开始的宿主重试、取消、未知状态分别展示；工具执行失败不把已成功结算的模型请求改成失败。
4. 当前价格快照按每次请求的时间、输入及缓存词元选峰谷价和上下文阶梯。金额不是历史账单，不含订阅费、充值和账号积分换算。未上报用量、未知模型价格、缺少缓存写价格的请求不计入金额，显示计价覆盖数量。
5. 响应耗时从步骤或重试开始到带定时流的模型结算，包含前置处理，不含后续工具。首词元按上游 `assistantStreamFirstTokenTime` 口径，包含文本、推理和工具参数。输出速度为同一批有正解码时长样本的输出词元总量除以解码总时长。旧消息缺定时流不补零。
6. 每会话均摊为已知成本除以含该模型请求的会话数。仅完整、全部计价、跨度至少一天的日期范围提供 30 天线性折算；最近 N 会话、空范围或读取不完整时不折算。这不是预测实际账单，也没有可核实的任务边界或任务质量分数。
7. 试算保持原请求的输入、输出、缓存词元和时段，按目标模型价格重算；目标上下文小于输入加输出时排除该请求。未知用量或价格单列。可见目录沿用适配器模型筛选，客观展示上下文、图片与推理力度；目录可能降级，不保证账号授权，也不校验图片、工具兼容性。换模型后的词元、缓存命中、重试与质量可能变化，不自动推荐、不调用模型。
8. 压缩摘要（`compaction/summary`，上下文压缩）的用量记在该事件上，此前历史分析会漏计这部分：压缩器自己发起的一次模型调用不落在任何 turn/step 上，也不产生 `request/header`。现在按事件自带的 `provider` 与 `model` 单独登记一条请求事实（`outcome` 记为 `completed`、不计重试），且只认 `provider === 'commandcode'` 的摘要，不继承上一条请求的模型选择——它没有 `request/header`，因此不存在「继承前缀模型选择」这一层，也不改相邻请求的 provider 状态。这是统计口径的变化：同一段历史重读后，计入的金额与词元会比旧口径更高。
9. 候选模型的 30 天试算为该模型试算成本乘以 `30 天 / 已观察时长`，观察终点取日期范围截止与报告 `generatedAt`（生成时间）中的较早者。仅历史读取完整、范围至少一天、非空且该候选覆盖全部请求时显示；基准历史缺价不影响可独立计价的候选。最近会话、缺价、未知用量或超上下文排除均给出中文原因，不把缺失值补零。
10. 成本差额为候选试算成本减去所选历史全部请求按当前价重算的成本，正数表示更贵。只有读取完整且两边均覆盖全部请求时比较；相同的部分覆盖数量不能证明样本相同。基准大于零时显示差额除以基准的百分比；基准为零仍显示金额差，但不生成比例。免费候选的零成本、零月度试算和零差额均为有效数据。

## 二、宿主对接与边界

1. 使用可选 `sessionQuery` 服务的 `listSessions()`、`readSession(id)`；读取优先实时会话，包含持久化关闭会话，返回精确 `inheritedEventCount`。不使用已弃用的同步事件读取、不把会话加载为实时、不直接扫描目录、不写回原始日志。没有服务时明确显示不可用。
2. 单次最多扫描最新创建的 500 个逻辑会话、累计 200000 个事件；最近会话排序在该已读取范围内进行。日志按宿主完整读取后再检查事件上限，大单条日志的读取峰值仍受宿主实现影响。超过上限、缺继承边界或不可读记录明确显示遗漏，关闭月度折算。筛选不保证超出上限的历史完整性。
3. 同一插件实例只执行一项历史统计；并发请求返回中文忙碌提示。取消在各次读取之间检查，宿主 `readSession` 没有取消参数，已在执行的一次完整日志读取不强行中断。
4. 分析模块只在宿主折叠期间处理原始消息，底层历史缓存的生命周期由宿主负责；远端仅返回按模型汇总的数值、筛选参数与能力，不返回会话 ID、正文、标题、工作目录、密钥。无新增持久化分析库。浏览器采用查询代次，卸载或重新绑定后丢弃过期结果。
5. 新增严格远端 `commandcode/analytics(query)`，宿主和客户端共用参数/响应编解码器；旧宿主缺接口时中文提示更新，其他设置与额度面板继续工作。既有适配器生成协议、会话费用投影和公开入口保持原契约。
6. 2026-10-15 的逐模型月度试算与成本差额由 `src/client/analytics-comparison.ts` 从同一份报告派生；远端字段、模型目录、历史读取与价格计算接口均无新增，不触发额外读取或模型调用。

## 六、界面与交互

1. 顶部筛选工具栏与结果范围分开：输入是草稿，读取后才更新总览。总览展示已知成本及计价覆盖、请求与会话数量、平均响应及首词元样本；读取不完整和未计价提示始终可见。
2. “历史用量”和“价格试算”采用分段页签，数量徽标显示完整模型数量。历史页默认比较成本、响应、首词元和输出速度，比例条为模型已知成本除以全体已知成本小计；没有计价样本或小计为零时显示“无占比”，已知零成本仍显示 `$0.0000`。模型名称复用同一报告中的试算目录，名称缺失时保留历史标识，不另读目录接口。模型展开后保留词元与缓存、请求状态、统计样本及每会话均摊，汇总明细保留总词元、状态与输出速度。
3. 价格试算支持本地名称／标识筛选；默认展示试算金额及计价覆盖、30 天折算、较历史基准的金额差与比例，缺失值附中文原因。展开查看计价、超上下文、未知数量及上下文／输入类型／全部推理力度。基准与折算条件常驻，覆盖不同请求的金额不能直接比较。空结果明确提示调整筛选，常驻短提示说明金额并非账单，统计说明可展开。
4. 第二版继承宿主字体与语义主题变量，采用胶囊筛选控件、0.5 像素细边框和 16 像素卡片圆角。筛选输入、下拉及读取按钮均为 36 像素高；箭头居中、右侧留白 12 像素且不截获点击。总览数字 20 像素，正文 14，辅助文字最低 12，页签 13；图标为线性单色 SVG（矢量图形）。
5. 分析页使用独立宽度和私有选择器；以面板实际可用宽度切换集中表头、逐指标标签与两列分组，窄屏英文页签允许换行。页签支持方向键及首尾键，明细支持键盘展开；操作和指标沿用宿主语言，错误、缺失与读取状态统一中文。第二版说明见[《模型分析第二版设计》](模型分析第二版设计.md)，页面重排不改变第一章的统计口径或历史读取时机。
